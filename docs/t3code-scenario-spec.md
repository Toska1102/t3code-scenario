# Agent 团队工作台产品与实施规格

**评审状态**　待需求负责人批准。批准前只交付本规格。批准后在本地按垂直路径拆票，再以独立 worktree 逐票执行。目标仓库为 `Toska1102/t3code-scenario`，评审基线为 `main` 的 `2fbb071`。

## 问题

用户希望按团队组织项目，用可复用的任务工作流描述一类工作，并用不同材料反复派发。用户需要看到每条任务实际调用的流程版本、运行到哪一步、何时需要评审，以及正式结果在哪里。设计稿已经给出了入口和操作路径。现有原型可供交互参考，正式实现需要把模拟流程、Agent 状态和结果替换为可恢复的后端行为。

## 方案

从团队首页进入团队项目列表或项目详情。在项目详情用两个并列模块管理任务工作流和项目任务。「描述要做的事」归入新建任务工作流。用户配置或确认流程后手动派发；每条任务直接归项目，并绑定所用工作流版本。组织架构与 Agent 连接通过按钮打开弹窗。任务详情统一展示进度、活动、评审、会话和结果。

前端独立部署。后端以完整 T3 Code 为基础，增加领域、应用和适配层，复用 T3 的持久工作流、人工答复、线程与 Pi、Codex、Claude Code 驱动。首版所有已认证的工作台用户均为管理员，评审负责人决定个人待办归属，管理员可代办并留下真实操作者。

### 设计稿与规则的优先顺序

- 界面和跳转以 Pencil 导出的十张业务画板及跨页标注为准。控件、状态、成功分支和失败恢复都进入验收。文字裁决适用于版本、计数、任务归属与状态转换。新增的空态和异常沿用画板的组件与入口。
- 画板中两张同名同版本的「简历审核 v1」分别显示两条和一条调用。按已经确认的口径合并为一个版本的三条任务调用，编号 #018、#024、#025。任务行和反向调用清单由同一个版本 ID 计算，计数随真实数据更新。
- 03.01 的「已确认 v1」用于明确基线。「查看流程」展示原版；「编辑流程」以该版本进入可编辑草稿，保存编辑不会改写历史。
- 组织架构 01.02 和 Agent 连接 05.01–05.03 为弹窗规范。项目列表、新建项目、待评审及错误恢复没有独立画板，使用本规格补充的规则。

## 用户故事与交互验收

### 01.01 团队总览、团队项目列表与 02.02 项目设置

1. 作为管理员，我可以通过首页标识回到团队总览，看到团队、项目和具体任务计数，知道当前工作范围。工作流草稿不计为任务。
2. 作为管理员，我可以在团队卡片看到团队名、描述、项目数及下属项目，点项目进入详情，点「查看项目」进入该团队的列表。没有项目时显示空态并保留新建入口。
3. 作为管理员，我可以在项目列表看到各项目的任务和工作流数量，只浏览所选团队或未分配范围。点卡片进入详情，返回后恢复原范围。
4. 作为管理员，我可以只填名称创建项目。来自某团队时预选该团队，可清空；工作目录可空。新项目从零任务和零工作流开始并进入详情；取消回来源。没有团队仍可记录或保存草稿，确认与派发前须选择团队。
5. 作为管理员，我可以编辑当前项目的名称、团队、本地工作目录。名称去除首尾空白后必填；保存失败保留输入。改名保持项目 ID；换团队或目录时说明对未来派发的影响。取消或关闭时保护未保存修改。
6. 作为管理员，我可以从团队卡、关联项目或任务打开对应团队的组织架构，在任一业务页打开 Agent 连接弹窗。关闭后回到原页、选中对象和触发控件。

### 01.02 组织架构

7. 作为管理员，我可以编辑团队名称、描述并查看节点数和绑定 Agent 数。组织草稿与团队信息一起保存，失败时可修正后重试。
8. 作为管理员，我可以在组织图选择节点，在属性区修改名称、岗位或能力类型、职责、执行者、汇报对象、评审规则、岗位提示词、工具、Token 上限和允许模型。
9. 作为管理员，我可以在选中节点下新增节点，未选时挂到根节点。根不可删；删除其他节点先预览下属及流程影响。孤立下属必须改挂或由我明确一并删除。
10. 作为管理员，我可以为非根节点选择一个或多个相邻层的上级。组织图为三层，根节点唯一。重复、自连、跨层、成环和悬空引用均定位并阻止保存。
11. 作为管理员，我可以将节点绑定人员、Agent 实例或留空。节点使用稳定 ID，改名保留引用；未绑定可保存，但相关流程确认前需补齐。
12. 作为管理员，我可以为适用任务类型配置评审节点与必审选项，并为岗位限定工具、模型与正整数 Token 上限。工作流仅可收紧这些约束。
13. 作为管理员，我可以预览并导入团队 YAML，校验格式版本、节点、关系和约束。失败保留原草稿；导入后可补绑人员或 Agent。导出包含规则与结构，排除凭据、私有绑定与设备路径。
14. 作为管理员，我可以看到组织变更对后续派发的影响。已派发任务保留流程、人员、评审规则和运行快照；兼容的变更允许继续派发。不兼容时定位步骤并引导修订及重新确认。

### 02.01 项目详情

15. 作为管理员，我可以在项目详情看到名称和团队，从面包屑返回所属项目列表，通过按钮打开项目设置与组织架构。未选团队时可补选。
16. 作为管理员，我可以用任务数和工作流数跳到对应模块。任务按独立执行记录统计，工作流按流程系列统计并包含草稿。空模块展示下一步。
17. 作为管理员，我可以在「新建任务工作流」描述一类工作并选取本次材料，看到文件名和数量，移除或替换单个附件。失败标明文件并保留其他输入；创建只进入草稿。重复提交可恢复同一草稿。
18. 作为管理员，我可以从流程目录编辑已确认版本、继续已有草稿或用已确认版本派发。每张卡显示名称、摘要、状态、版本与真实调用；点击任务编号可定位到该任务。
19. 作为管理员，我可以从项目任务直接打开运行进度、处理评审、查看结果或查看实际调用版本。标题相同的任务由编号区分，反向引用与任务行共享版本 ID。
20. 作为管理员，我可以看到「待我处理」数量，单条直达待评审节点，多条定位待处理列表。计数按负责人归属；其他管理员通过任务详情代办。

### 03.01 工作流编辑器

21. 作为管理员，我可以填写流程名称、描述、派发输入和交付物。首版输入支持短文本、长文本和文件，每个字段定义标签、稳定标识、必填性和说明。删除字段时显示受影响步骤。
22. 作为管理员，我可以手动选参与成员，查看自动纳入的所有上级路径直到根节点。重复上级只展示一次，取消成员后保留其他路径仍需要的人。自动纳入只决定候选范围。
23. 作为管理员，我可以生成和重新生成流程草稿，查看成员匹配和必审依据。重生成前显示覆盖范围，失败保留上个草稿；缺成员、绑定或评审时指出缺项。
24. 作为管理员，我可以添加或选择步骤，编辑名称、负责人、执行方式、依赖、输入来源、输出、提示词、工具、Token 和模型。删除步骤或依赖先显示影响，缺失输入须补齐。
25. 作为管理员，我可以拖端口连接步骤，选中连线后删除，拖动节点并使用自动布局、放大、缩小和适应画布。画布拒绝重复边、自连和成环；布局和缩放不改变执行依赖。
26. 作为管理员，我可以保存未完成草稿，或在组织、流程结构、输入输出、成员和必审规则通过后「只确认工作流」。Agent 离线、不齐的本次材料或缺少运行目录不影响合法的流程确认。
27. 作为管理员，我可以查看历史版本、从确认版本建立修订草稿，在通过校验后确认新版本。返回项目时恢复选中流程，未保存时先提示。已派发任务始终读取原版本。

### 03.02 任务派发

28. 作为管理员，我可以从草稿继续首次派发，核对将确认的版本和本次材料，按表单定义填写输入。简历审核示例要求岗位、岗位要求和至少一份有效简历。
29. 作为管理员，我可以从确认版或历史任务再次派发，默认沿用所选确切版本，并可显式切换到其他已确认版本。已有任务列表仅显示同一版本。上次材料需明确选择复用。
30. 作为管理员，我可以看到本次派发的结构和运行校验。缺材料、团队、岗位绑定、模型验证、Agent 可用性、可执行的工具及 Token 硬限制或所需目录时，提示具体步骤与修复入口。返回表单保留本次材料。
31. 作为管理员，我可以在组织规则变更后继续处理原派发。提交时读取当前组织修订，兼容则采用该修订创建任务，不兼容则保留输入并引导修订流程。修订后匹配相同字段，明确显示新增必填项。
32. 作为管理员，我可以用「确认并派发」确认版本并记录一条任务，或用「派发并运行」创建新任务。提交期间禁用重复操作；网络结果未知时查找或重试原提交；成功后打开该任务。取消或关闭按规则处理草稿。

### 04.01 运行、评审、会话与结果

33. 作为管理员，我可以在项目任务栏切换任务，同时切换步骤图、状态、活动、评审、会话与结果。返回项目或打开发生问题的组织和 Agent 弹窗时保留上下文。
34. 作为管理员，我可以看到本次执行的步骤、状态与完成计数。前置齐备的分支可并行，汇合等待所有直接上游成功；失败和受阻有明确原因。T3 重启后可继续查看和恢复。
35. 作为管理员，我可以按步骤定位 AgentTrail 活动，点击活动回到所属步骤。活动未关联或 AgentTrail 不在线时展示原因和重试，仍可查看任务与评审。
36. 作为管理员，我可以打开项目助手、步骤线程或只读观察会话，看到对象、任务和步骤范围。发送非空消息后查看进度，失败能重试。切换任务或会话时，草稿、消息和迟到回复归各自原上下文。
37. 作为管理员，我可以查看待审产出并代办开放的人工评审。系统分别记录指定负责人、当前登录操作者、时间和产出尝试。其他人已处理时显示该状态，重复提交不能产生额外评审结果。
38. 作为管理员，我可以填写原因、指定返工目标并看到受影响下游，退回后创建新尝试。依赖该产出的评审须重新完成；无依赖的分支和历史意见保留。通过后只解锁满足依赖的后续步骤。
39. 作为管理员，我可以从「查看结果」直达同一结果区，阅读摘要和文本、打开或下载文件、回看本次材料、运行版本及评审记录。执行和必审均成功、正式结果已保存才显示完成。
40. 作为管理员，我可以在结果保存失败时重试同一正式产出。任务保持待处理，已完成步骤和评审保留。已完成任务读取失败时只重试读取，完成状态保持。
41. 作为管理员，我可以从运行详情查看确切原版本或用此流程再派一单。运行已完成、失败或取消后，历史仍可回看。

### 05.01–05.03 Agent 连接

42. 作为管理员，我可以看到本机 Agent 实例的总数、可用数、默认标记和检查状态，切换 Pi、Codex、Claude Code 时保留各自未保存的配置。
43. 作为管理员，我可以分别启停实例、切换默认、检查 CLI 和认证，看到最近检查时间、版本、模型发现状态与失败原因。已启用但待认证不计可用；默认最多一个。
44. 作为管理员，我可以配置可执行文件、启动参数和各自配置目录。Pi 展示其 AgentTrail 扩展状态；Codex 支持其主目录和启动设置；Claude Code 支持自定义端点、上下文压缩阈值和空闲压缩策略。
45. 作为管理员，我可以添加、编辑、删除环境变量，默认看到密钥遮蔽值。诊断和 YAML 不含密钥；被引用的实例或模型停用前展示影响。
46. 作为管理员，我可以查看模型来源及状态，收藏与启停模型，添加自定义模型 ID。拒绝重复或无效 ID；验证成功且启用后才有派发资格。
47. 作为管理员，我可以保存、放弃修改、关闭弹窗。健康检查不自动保存编辑或派发；关闭未保存弹窗会提示。保存后更新全局指标。
48. 作为管理员，我可以在真实 Pi、Codex、Claude Code 中分别完成连接检测、一个任务步骤和会话续接。某个实例无法保证指定工具权限或 Token 硬上限时，派发阻断并指明步骤、实例和原因。执行已开始的步骤用自身快照；未开始的步骤再检查实例，停用后显示待处理。

## 实施决策

- **领域层**负责组织关系、流程版本与依赖、成员集合、评审尝试和任务完成不变量。依赖限于业务值与规则。
- **应用层**负责确认工作流、派发任务、决策评审、保存正式结果以及项目聚合查询。应用层定义存储、运行、生成与文件接口。前端用 HTTP 与任务级事件，数据归属与状态转换由服务端决定。
- **适配层**实现 HTTP、SQLite、文件、YAML、LLM、AgentTrail 和 T3 接口。数据库或文件存储可在组装处切换。前端保留现有原型的交互组织，后端替换模拟状态、浏览器持久化与固定样例。账号鉴别记录实际管理员，业务角色保持单一。
- **T3 执行**采用固定可信执行器读取结构化工作流快照。复用持久步骤、Agent 线程、模型及实例能力、`ask` 等待和 `answer` 当前答复。工作台业务版本和 T3 执行器版本分别记录，均不得隐式取最新。画布、YAML、模型输出均作数据校验。项目助手和真实步骤线程各用自己的传输范围。
- **派发一致性**。提交时基于同一当前组织修订完成校验和快照登记。在业务事务中保存新版本（首次适用）、任务、提交回执及持久启动意图。提交后启动 T3。任务启动键稳定，丢响应或进程重启可重新取回同一运行。事务回滚时不会启动外部运行。真实启动失败保留可恢复的具体任务和输入。
- **结果一致性**。执行引擎的成功作为步骤事实；工作台保存正式交付物及结果清单后才发布任务完成状态。结果重试使用固定的产出标识。T3 的摘要和可能截断的步骤记录可供展示，正式文件单独保存。
- **接口行为**。任务详情先获取快照再订阅增量，断档回读快照。显示错误按对象、字段或步骤定位。弹窗管理选择、滚动和焦点，服务端识别重复写入并保留真实审计记录。

## 测试决策与门控

- **浏览器层**按 01.01、01.02、02.01、02.02、03.01、03.02、04.01、05.01、05.02、05.03 及跨页标注逐项覆盖。每项标明入口、输入、状态、预期和测试，至少覆盖首次派发、复用历史版本、失败修复保留材料、待办和代办、退回、正式结果和弹窗返回。样例项目与任务用于演示断言。
- **后端用例层**通过公开的确认、派发、评审、结果及读接口测试，不窥探具体实现。SQLite 实现使用同一套契约验证事务、重启恢复、重复提交、组织修订竞争和对外状态。TDD 先建立可失败的测试再实现。前端和后端使用一致的错误契约。
- **真实 T3 集成层**复用 T3 既有工作流、评审及提供方测试结构。对 Pi、Codex、Claude Code 分别验证连接、执行、线程续接和硬限制无法保证时的阻断。验证并行汇合、等待评审和服务重启。另验证真实附件读取、文件结果与 AgentTrail 缺失时的降级。没有真实环境证据的项保持待验收。
- **编码前 LLM × SMT**。从控件动作与领域状态分别推导解释，模型自身分歧触发具体反例。以命名断言运行 SMT，保留正例、反例、最小冲突集和裁决。至少覆盖组织修订竞争、确认和派发门槛、同版本调用、幂等、个人待办与代办、评审尝试、停用后的步骤、结果原子完成和失败重试。任何尚无裁决或求解为 `unknown` 的规则回到规格。SMT 证据与真实环境验收分别记录。
- **交付顺序**。本 Draft PR 是第一道人工作业门控。批准后使用 `to-tickets` 将任务拆为可独立验收的垂直切片，票只保存在本地，列出真实依赖。可并行票各由一名子代理在独立 worktree 执行 `implement`，逐票 TDD、代码审查和提交。所有票合并后对完整 diff 做 PR 级 Review，再提交用户验收。

## 首版范围

- 首版部署按一台运行设备、SQLite 和手动派发。日历调度、定时任务、跨项目共享流程、多设备选择、项目级 Agent 配置覆盖、角色分级均留作后续范围。所有人管理员的规则适用于已认证工作台用户。
- 文件类型白名单、单文件与批量上限，及具体凭据探测兼容组合，以真实 T3 验证后的规格补注为准。初始实现不接收不能安全验证和读取的文件路径。连接授权由提供方和设备处理，仓库不保存凭据。
- T3 执行器的注册入口、附件传递、硬限制、AgentTrail 事件关联为首个纵切的验收重点。任一真实能力不足时，按本规格的失败路径显示并在 PR 记录覆盖情况。
