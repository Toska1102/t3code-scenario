# Agent 团队工作台需求规格

用户从团队首页选择项目，在项目内创建或复用任务工作流，再手动派发具体任务。工作流定义一类工作的做法，任务保存一次工作的输入、执行版本、进度和结果。团队组织架构提供执行岗位、汇报关系和评审规则。Agent 连接按设备配置，组织架构与 Agent 连接均从按钮打开弹窗。[Pencil 设计稿](Design.pen) · [领域词汇](../GLOSSARY.md)

## 1. 基线与范围

- **画板基线**为 Pencil 导出的 01.01–05.03 共十张 HTML。以下交互表逐页记录画板出现的操作。HTML 是静态导出，页面跳转来自标注，表单的校验、失败、权限和持久化行为由本规格补齐。样例项目名、计数、版本、时间、模型与文件内容均为示例值。
- **首版入口**包括团队首页、团队项目列表、项目详情、项目设置、工作流编辑器、派发弹窗和任务详情。组织架构与 Agent 连接使用全局或当前团队的弹窗。项目列表、新建项目、待评审、异常和空状态未各自拥有独立画板，见对应补充要求。顶部保留首页入口、上下文面包屑、返回和 Agent 连接。任务工作流从项目进入。
- **首版只手动派发。** 自动定时、无人确认自动派发、跨项目共享工作流、设备间同步凭据均超出本规格。真实 Agent 执行、AgentTrail 活动接入及模型能力验证需要集成验收。设计样例中的会话错误是失败状态样例。

### 实体与归属

| 对象             | 归属与识别                                                    | 用户可感知的规则                                                   |
| ---------------- | ------------------------------------------------------------- | ------------------------------------------------------------------ |
| 团队             | 团队 ID，持有组织架构，可有零个或多个项目                     | 同一团队的组织设置可从任一关联项目打开。                           |
| 项目             | 项目 ID，至多选择一支团队，持有名称和可选工作目录             | 可先建项目。项目任务与任务工作流分别列出，切换项目后两者随之切换。 |
| 组织节点         | 团队内稳定 ID，含层级、负责人绑定、职责和能力限制             | 负责人可为人员或 Agent 实例。显示名变化时保留引用。                |
| 任务工作流及版本 | 项目内流程 ID，确认后产生不可变版本 ID                        | 工作流可重复使用。草稿可编辑，历史任务仍使用派发时的版本。         |
| 工作流步骤       | 版本内步骤 ID、负责人、执行方式、输入输出、能力限制及前置依赖 | 多个步骤可由同一组织节点承担。前置依赖构成有向无环图。             |
| 具体任务         | 项目内任务 ID、显示编号、工作流版本 ID、本次输入及运行快照    | 任务直接属于项目。不同派发分别保存状态、产出、评审和会话。         |
| 运行视图         | 具体任务的运行进度、活动和会话模块                            | AgentTrail 补充活动证据，执行与评审状态由工作流运行记录提供。      |
| Agent 实例       | 运行设备上的稳定实例 ID，包含提供方、配置与模型               | 组织节点绑定实例 ID。默认实例只用于初始推荐。                      |

### 通用交互约定

**首版操作路径**。确认可复用的流程，手动派发一条任务，处理待评审节点，再从任务详情的「结果」区交付。新任务和历史任务都使用这一条入口。

- 同一业务对象的所有入口解析同一 ID。找不到、已删除或无访问权限时显示原因与安全返回入口，无自动替换为别的项目、任务或流程。数量由当前范围的记录计算。
- 表单保存中显示进度并防止重复提交。校验失败定位字段或节点并保留输入；服务失败保留草稿及重试入口。成功后更新来源页的计数、状态和已保存值。同一保存请求重试应产生相同结果。
- 弹窗打开时焦点进入标题或首个可编辑控件，背景暂不可操作。关闭按钮、取消、Esc 和允许的遮罩关闭走相同退出规则。未保存的修改需要提供继续编辑或放弃选项。关闭后恢复原页面、滚动、选中对象和触发按钮焦点。
- 输入、附件、配置和运行记录按所属项目或团队隔离。首版所有工作台用户均为管理员，可查看工作台数据，管理团队、项目、流程、Agent，派发与处理评审。组织节点指定的评审人用于显示负责人和待办归属；其他管理员也可代办，记录实际操作者。操作仍受对象归属、当前状态与执行环境校验约束。

### 团队项目列表与新建项目（补充）

- 打开团队项目列表时只显示该团队所辖项目。项目卡显示名称、任务数和工作流数，点卡片进入 02.01。返回团队回到来源卡片。02.01 的「返回项目列表」返回所属团队；未分配项目回到未分配项目列表。
- 点击「新建项目」复用 02.02 表单，标题为「新建项目」。项目名称必填；从团队列表进入时预选该团队，可改选或清空；工作目录可空。提交成功进入新项目详情，新项目的任务与工作流数量均为零。取消回来源列表。无团队项目可描述、保存草稿和录入材料，确认工作流或派发前需选择团队并校验节点绑定（R03）。

### 组织变更如何生效

- 保存组织配置时展示受影响的项目和已确认流程，并提示哪些绑定、必审或岗位约束需要在后续派发复核。保存只写当前团队配置，已派发任务的参与者、评审规则、运行和结果继续使用原快照。
- 对新派发使用当前已保存的组织配置。兼容的变更允许继续，例如只修改节点显示名且引用 ID 不变。若岗位移除、人员或 Agent 绑定不再有效、增加必审且现有流程未覆盖，或收紧的限制与步骤配置冲突，则定位到对应步骤。修订并重新确认通过后可继续派发。旧版本和历史记录保留。
- 派发提交时复核当前规则。预检后如果组织被改动，以提交时读到的规则重新校验。兼容则用这一版快照创建任务；不兼容则不创建任务，返回原表单并保留输入。校验与绑定快照使用同一版本，避免在两次读取之间采用不同配置（D02）。

组织样例为 HR 根节点，下设 OD、TD、招聘、C&B、ER、Culture、SSC；SSC 下设 TA、入转调离、薪酬核算和社保公积金。手动选中 TA 时自动纳入 SSC 与 HR，并在成员选择中保留来源路径。[01.02 组织架构](design-html/01-02-organization.html)

## 5. 工作流编辑器

### 03.01 生成、配置与版本

| 控件或区域                                | 触发与结果                                                                                         | 校验与例外                                                                                                            |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 任务名称、这件事通常怎么做                | 编辑流程名称和自然语言描述。首次进入带入项目中的描述。                                             | 用词区分流程名称与派发后生成的任务标题；名称去空格后必填。                                                            |
| 派发输入、交付物                          | 编辑字段定义、必填性与输出说明。简历审核样例为岗位、岗位要求、待审核简历，以及经复核的建议。       | 移除某字段时提示哪些步骤读取它。派发表单由确认版本的字段定义生成。                                                    |
| 参与成员                                  | 用户手动勾选本团队成员；显示直接选择和自动纳入的全部上级路径直到根节点。                           | 多条路径去重；取消一个成员时保留仍由其他成员引用的上级。上级纳入仅代表有资格参与（R05）。                             |
| 生成／重新生成草稿                        | 基于描述、已选成员、职责和评审规则生成步骤、依赖、所需输入及产出。展示角色选择和必审依据。         | 缺角色时提示选择或补齐。重生成已有草稿时先提示覆盖范围。失败保留之前的内容。                                          |
| 添加步骤、选择步骤                        | 添加后自动选中，右侧显示该步骤的名称、负责人等配置。                                               | 尚未配置的步骤可保存草稿，确认前需补齐。                                                                              |
| 连接、选线和删除线                        | 从输出端口拖到输入端口创建有向依赖。选中连线后按 Delete 删除。                                     | 拒绝重复、自连、成环或失效端点，提示问题所在。删除连线后重新校验受影响的输入。                                        |
| 拖动、自动布局、放大、缩小、适应画布      | 改变节点位置或缩放，保留步骤和依赖。                                                               | 自动布局不改变执行顺序。空画布禁用布局操作。                                                                          |
| 步骤名称、负责人、执行方式、依赖步骤      | 名称必填；负责人从参与成员集合选择；方式为执行或人工必审；依赖可在画布或属性区调整。               | 无前置时为起始步骤。人工必审可为起始步骤并等待人工操作。删除步骤前列出受影响依赖。                                    |
| 步骤输入、输出、提示词、工具、Token、模型 | 绑定输入来源，声明产出和可选提示词；选择与岗位能力匹配的工具和模型，设置预算。                     | 前置产出必须存在，禁止超出岗位边界。人工评审不启动模型。汇合节点等待所有直接上游完成（R06）。                         |

## 9. 编码前的 LLM 与 SMT 校验

本轮先由同一 LLM 从画板做交互提取，再分别推演两种解释。第一种保留控件或文案的直接含义，第二种从实体归属、版本与状态转换推演边界场景。把两种解释出现不同结果的场景送入 Z3 4.13.4。用命名断言跑可满足性，并逐项移除断言以得到**包含意义下最小的冲突集**。下面的反例说明规则为何无法在同一场景下成立。仅 R01 是已观察到的示例归属冲突。其余是某种解释与已选产品规则合用时的冲突，分别注明边界和裁决。

| 编号及来源                        | Z3 给出的最小冲突集                                                                                                                                                                                             | 采纳规则与复验                                                                                                                                                                               |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| R07 · 05.01 · 启用与可用          | Pi 已启用；Pi 未认证；可用需要启用并认证；启用即等于可用。                                                                                                                                                      | 把启用、认证、可用分别显示和校验；SAT。                                                                                                                                                      |
| R08 · 05.03、03.02 · 自定义模型   | 模型被启用；模型未验证；参与派发需验证；启用自动取得派发资格。                                                                                                                                                  | 允许配置待验证模型，新任务仍须先通过验证；SAT。                                                                                                                                              |
| R09 · 05 系列、04.01 · 停用时机   | 实例已停用；已存在运行；当前步骤允许按快照继续；停用必然中止当前执行。                                                                                                                                          | 停用阻止新派发。已有步骤按快照继续；连接故障另走失败或阻塞；SAT。                                                                                                                            |
| R10 · 03.01、04.01 · 退回         | 执行在评审之前；退回作为版本依赖时要求评审又在同一执行之前。                                                                                                                                                    | 退回创建新的执行尝试，保持版本图无环；SAT。                                                                                                                                                  |
| R11 · 04.01 · 会话作用域          | 当前任务是 #025；用户发送消息；发送的会话必须归当前任务；沿用 #024 会话。                                                                                                                                       | 会话按任务及步骤标识独立保存；SAT。                                                                                                                                                          |
| R12 · 02.02、03.02 · 工作目录     | 流程需要本地文件；目录不可用；开始需可用目录；目录可选被解释为仍可派发。                                                                                                                                        | 项目设置允许为空，按流程使用情况在派发前检查；SAT。                                                                                                                                          |
| R13 · 05 系列 · 默认实例          | Pi 不可用；Codex 和 Claude Code 都可用；示例设备只有一个默认；所有可用实例都是默认。                                                                                                                            | 一个设备最多一个默认，多个实例仍可同时可用；SAT。                                                                                                                                            |

另外在组合规则下检查了十个场景。无团队建项目、首次合法派发、等待并行分支、两分支完成后评审、#025 发送到本次会话、Pi 未认证时保持待配置均为 SAT。跨任务发送、分支未完就评审、未选团队派发、需要本地文件却缺少目录时派发均为 UNSAT。结果只覆盖建模的逻辑和样例。SAT 表示这些规则可以同时成立，实际接口、权限、并发和运行接入仍需测试。

补充裁决后另用 Z3 检查了 9 个组合场景。管理员处理待评审、离线时只确认、规则变更后查看历史、满足条件后派发、保存结果后完成可成立。处理已结束评审、离线派发、规则不兼容时派发、缺少最终结果却标记完成均不可成立。

### 本次深化 · 从交互分歧到最小冲突集

本次对同一份需求分别做两遍推演。第一遍沿用户点击顺序解释按钮，第二遍按版本快照、权限归属、执行尝试和保存状态逐条推导。两遍对同一反例得出不同结果时才进入下表。使用 Z3 4.13.4 的命名断言检查冲突，并逐条移除仍可保持 UNSAT 的断言。表中冲突集均为包含意义下最小。D01–D11 的取舍按本版规格执行。

| 分歧编号与交互                | 无法同时成立的断言                                                                             | 采用规则与求解结果                                                           |
| ----------------------------- | ---------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| D01 · 只确认                  | 设备离线；流程允许确认；确认必须等设备可用。                                                   | 确认校验流程定义，设备就绪在派发时检查。UNSAT → SAT。                        |
| D02 · 派发时的组织变更        | 预检读取组织版本 1；提交时当前版本是 2；本次启动必须使用当前快照；任务启动；启动沿用预检快照。 | 提交时以版本 2 重新检查。兼容时使用版本 2，检查失败时保留输入。UNSAT → SAT。 |
| D03 · 管理员代办              | 负责人为甲；操作人为乙；乙为管理员；评审待处理；管理员可代办；只有负责人可评审。               | 乙可处理。在事件中分别记录甲和乙。UNSAT → SAT。                              |
| D04 · 待我处理                | 存在一条归别人的待评审；个人待办按负责人归属统计；个人待办计数等于所有有权代办的事项数。       | 「待我处理」只计归本人事项。UNSAT → SAT。                                    |
| D05 · 返工后的评审            | 通过的是尝试 1；当前产出为尝试 2；交付要求当前尝试的评审；旧通过记录足以交付。                 | 受影响的产出重新评审。旧意见仍可查。UNSAT → SAT。                            |
| D06 · 完成状态                | 正式结果保存失败；任务完成需要保存结果；步骤完成即可标记任务完成。                             | 保持「待处理」，等待结果保存。UNSAT → SAT。                                  |
| D07 · 重试保存                | 重试沿用已完成执行；重试必须再执行步骤。                                                       | 重试只保存已生成的正式结果，复用同一次审核和产出。UNSAT → SAT。              |
| D08 · 重复派发                | 同一次提交的请求必须映射到同一个任务；每次请求创建不同任务。                                   | 同一次提交只创建一个任务，另发一单才换提交标识。UNSAT → SAT。                |
| D09 · 停用 Agent 后的后续步骤 | 实例已停用；启动步骤需要实例启用；队列里尚未启动的步骤继承了在途步骤的放行。                   | 在途步骤沿用快照，后续步骤开启前重检。UNSAT → SAT。                          |
| D10 · 历史任务查看流程        | 任务使用 v1；当前最新为 v2；任务详情打开派发快照；查看流程打开最新版。                         | 历史入口打开确切版本。再次派发允许用户明确选新版本。UNSAT → SAT。            |
| D11 · 已完成结果读取失败      | 任务已完成；当前读取暂时失败；读取失败应撤销完成状态。                                         | 完成记录保持，单独显示获取结果失败和重试。UNSAT → SAT。                      |

组合验证另跑了四个跨阶段场景。「离线时可确认草稿形成版本」和「满足条件后派发、通过评审并保存结果」为 SAT。「按已失效规则派发」和「未保存最终结果即完成」为 UNSAT。验证只覆盖明确建模的交互条件；浏览器持久化、真实账号、文件权限、运行时和并发提交需分别实现和验收。

### 后续编码门槛

1. **先建需求断言。** 每次变更先由 LLM 分别从用户动作和数据状态推导解释，记录具体来源、条件、允许或禁止的输出。不同解释产生不同结果时先保留双方，再建立反例。
2. **求解并复核语义。** 布尔变量表达门槛和转换，整数表达版本号、依赖拓扑位置与计数，实体 ID 表达任务和版本归属。可满足时提取示例核对语义；不可满足时定位命名规则的最小冲突集。让 LLM 和需求方核对结果，再选定规则。无法判定时记录待裁决项，避免以默认值掩盖分歧。
3. **再编码和验收。** 触发代码生成前必须记录需求编号、反例、求解结果与裁决。凡同一需求的正例不成立、反例仍可成立、求解返回 unknown，或语义尚无明确裁决，先修规格。实现后将这些场景转为验收测试；规则变更先重跑求解再修改实现。
